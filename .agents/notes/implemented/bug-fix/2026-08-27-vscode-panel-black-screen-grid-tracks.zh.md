# Agent Note：内嵌面板黑屏来自「三轨网格配两个子元素」

Status: implemented

[English](2026-08-27-vscode-panel-black-screen-grid-tracks.md) | 中文

## 问题

VSCode 面板渲染成黑屏（「先出现加载动画，然后一片黑」），而面板内的 SPA 被证明完全健康。每一层都查过：隧道的 WebSocket 下行流建立成功、所有启动 RPC 返回 200、启动探针报告脚本全部加载、webview 内部的 DOM 自检报告 hero 视图正常渲染且颜色/尺寸/布局正确。面板 iframe 在屏幕上的矩形 1349×918 正常。连软件渲染（`--disable-gpu`）也黑。同一 VSCode 里 Claude Code 的面板正常。症状指向了除真实 bug 以外的一切。

## 决策

根因：`AppFrame` 的内嵌模式渲染两个网格子元素（中栏 + 详情栏——侧栏列被跳过），却保留了普通模式的三轨 `grid-template-columns`（`0px minmax(0, 1fr) 0px`）。网格自动排布把中栏（整个 hero/对话表面）放进了零宽的第一轨，而详情列——一个空的、透明的、占满 `1fr` 的轨道——覆盖了整个视口。页面渲染完全正确，只是被放到了屏外，头顶还盖着一层透明列。修复：内嵌模式改用两轨模板（`minmax(0, 1fr) ${details}px`），中栏排第一。

## 已考虑的替代方案

排障中没有备选修复——根因是诊断探针指向覆盖的详情列之后才找到的，修复就是上面最小化的模板改动。真正被考虑并逐一否决的是替代*解释*：隧道 WebSocket 中继（open 日志与 RPC 200 证明工作正常）、被 CSP 拦截的样式表（webview 内计算出的深底亮字推翻了它）、GPU 合成器（`--disable-gpu` 依旧黑屏推翻了它）、以及应用层覆盖遮罩（直到发现遮罩就是网格本身才结束）。

## 后果

- 面板恢复显示 hero/对话表面。
- **诊断纪律**：单元测试只断言了模板*字符串*而非*布局*；无头模拟器只断言了 DOM 文本而非视口中心命中的元素。两者都漏掉了这个 bug。教训：当「DOM 正常但屏幕空白」时，去探测 `document.elementFromPoint(center)` 以及任何矩形覆盖视口 ≥90% 的元素——全量探针正是靠 `center=DIV.detailsCol` 覆盖屏幕这一条定位的。
- 面板新增了综合诊断探针（DOM 形状、覆盖层、视口中心元素、CSS 样式表加载状态、捕获的 JS 错误、焦点、计算样式），在 8s/25s/50s 采样——这把数小时的排查变成一行答案。
- 探针模板必须保持纯 JS：早先两个版本把 TypeScript 语法（`frames[0]!`、`(): void`）写进了浏览器字符串，以 `Unexpected token '!'`/`')'` 死掉，静默杀死了它们自己的上报。模板现在带有显式的「禁止 TypeScript 语法」注释。
